## 数学内容与核验方式

新增种子题中，28 道有结构化 `spec` 并由现有数学工具重算；39 道为解释、反例或需要完整解族／多项结果的题目，附完整参考论证和至少三项具体评分要点，标记 `dimension: explanation`，由模型按 rubric 评阅。全库共 89 道结构化题、42 道解释题。

不为没有对应核验操作的题型编造 `operation`，不把解是否存在、方程组、曲面或证明编码成一个任意数字冒充标准答案。曲线／曲面积分的可计算题用正确参数化后的标量积分作核验载体；题干、参数方向、微元及 `spec` 的对应另外做数学审校。

重点核对了以下条件：

- 单侧与双侧极限、对数定义域、闭区间最值定理、连续与可导的区别。
- 反常积分在奇点两侧独立取极限；主值为零不代表通常反常积分存在。
- 微分方程的零解、两个独立常数、重根、共振及欧拉方程的二阶导数修正；参考解均代回原方程检查。
- 多元极限的路径反例、偏导存在但不可微的余项反例、混合泰勒项系数。
- 球坐标 Jacobian、质心的质量归一化、曲线弧长与曲面面积因子、路径与法向定向；开半球补面后再使用高斯公式。
- 级数必要／充分条件、条件收敛、幂级数端点、傅里叶常数项和一般周期频率。

除入库数学检查外，58 项参考计算／保留旧内容／入库检索核对已通过，具体脚本和结果保留于本地忽略目录 `backend/data/C3-acceptance/`。这些是参考解的交叉核对，不是形式化证明检查，也不是实时模型验收。

## 验收与复现

在 `backend` 目录，用项目隔离环境执行：

```bash
uv run python -m app.knowledge check
LLM_API_KEY='' VISION_LLM_API_KEY='' uv run pytest -q tests/test_content_c3.py tests/test_knowledge.py
LLM_API_KEY='' VISION_LLM_API_KEY='' uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run python -m app.openapi --check
```

`test_content_c3.py` 对照原始《高等数学目录》检查全部节号、标题和考试标签，并逐知识点核对错因、典型错例、可检索的完整策略卡与验证种子题。现有内容检查核验全部结构化题与追问区分度；C2 的独立追问与种子题验收继续执行。

临时隔离业务库连续入库两次，计数均为 80／93／27／131；从库重建图谱后，全部 80 个知识点可检索到错因、策略和验证种子题。未向任何既有业务库插入学生、教学任务、掌握结论或证据。全部旧题目、旧错因、旧策略逐字段不变。

当前结果：内容检查零错误；覆盖与知识模块定向回归 12 passed。全量回归与复审结果在最终提交前更新。

## 运行边界

C3 交付的是内容库。当前 `StudentQuestions.solve` 对无法完整写入 `ItemSpec` 的原题会拒绝受理，辅导追问也要求可核验的标量 `spec`；因此补齐全书内容不会自动让 T15 支持任意证明题、微分方程求通解或其他无法完整结构化的题目。

评委跨章节自由提问的真实支持范围还需按题型核对；上述入口边界应作为体验联调中的功能问题单独处理，不能用“C3 已覆盖”代替运行验证。本批不修改或绕过已有核验、诊断、教考隔离与证据规则。

内容合入后，需要对目标业务库正常运行 `uv run python -m app.knowledge ingest` 并重启后端，以重建内存图谱；仅更新 YAML 不会自动更新已运行实例。新增内容使用新 ID，保留历史证据所引用的原题。

# 教学内容填写指南（C1）

本目录存放由数学教师编写的教学内容，格式是 YAML。系统的知识图谱、错因诊断、出题和验证都读取这里的内容。

| 路径 | 内容 |
|---|---|
| `lectures/01.yaml` 至 `lectures/12.yaml` | 每讲一个文件，已经按《高等数学目录》生成好全部 75 节的骨架 |
| `template.yaml` | 填写模板，以第二讲“多层复合函数求导”为例，每种条目都有一份示例 |
| `drafts/` | 模型起草、等待教师审核的判别追问题 |
| `deliveries/C2.md` | 精修内容清单、数学审校依据和验收记录 |
| `deliveries/C3.md` | 全书基础覆盖、补充内容的核验方式和验收边界 |

模板仅作参考，不属于入库目录；其中演示 ID 已用于 C2，不能再复制出同 ID 条目。新增题目应选新 ID。正式入库只读取 `lectures/*.yaml`。

## 讲次文件的结构

每个讲次文件有五部分，除 `lecture` 外都可以省略。ID 全书唯一，可以引用其他讲的内容。

| 部分 | 说明 |
|---|---|
| `sections` | 本讲的节：节号、标题、考研数学一/二/三标签（`math1`、`math2`、`math3`）。已按目录生成，一般不用改 |
| `points` | 知识点：ID、所在节、名称、先修知识点 `prerequisites`；`exam_tags` 省略时沿用所在节的标签 |
| `misconceptions` | 错因 |
| `strategies` | 策略卡 |
| `items` | 判别追问题和种子题 |

初始骨架为每节生成了一个知识点，ID 形如 `calc.ch3.s2`。C3 已为剩余骨架知识点补充先修关系、典型错因与验证种子题。教师可以继续把一节拆成几个知识点、改名，并完善关系。两条精修路径（第 1→2→9 讲、第 4→5→10 讲）涉及的节已经细化，例如 `calc.ch2.chain_rule`、`calc.ch10.polar`。改动已被引用的知识点 ID 时，要同时改掉所有引用。

## 需要教师编写的内容

按《技术文档》第 6 节的要求：

| 内容 | 精修路径 | 其余知识点 |
|---|---|---|
| 错因 | 每个知识点 2 到 4 个：ID、描述、错因族、可能复发的知识点 `recurs_in`，以及 1 个典型错例 | 每节至少 1 个高频错因 |
| 判别追问题 | 由模型起草，教师审核 | 不需要准备 |
| 策略卡 | 按错因族编写：教学原则、禁用做法、解释题评分要点，不写逐步教学流程 | 按错因族复用 |
| 种子题 | 含结构化描述 `spec`；普通验证分别准备计算正确性、抗诱错和近迁移题 | 每个知识点至少 1 道 |

教师只写模型做不准的部分：错因的界定、跨章节的复发关系和教学原则。追问题、讲解和练习题由模型当场生成，再由程序和核验工具把关。

## 公式写法

- 题干、标准答案、预测答案用 LaTeX，并用单引号括起来，如 `'6\sin(3x)\cos(3x)'`。
- 题目的结构化描述 `spec` 用 SymPy 语法，如 `sin(3*x)**2`，程序按它重新计算标准答案。`operation` 可以是 `expression`、`derivative`、`indefinite_integral`、`definite_integral`、`double_integral`、`limit`。
- `derivative.variables` 按求导次序排列：`[x, x]` 为二阶导，`[x, y]` 为先对 x 再对 y 的混合偏导。
- 定积分和二重积分写 `bounds`，由内到外排列，内层界限可以依赖外层变量。极坐标题的 `spec` 仍用原直角坐标描述区域和被积函数，让学生完成换元，不能预先把漏乘 r 等错误放进 `spec`。
- 极限题写一个变量、`limit_point` 和 `limit_direction`（`+`、`-`、`+-`，默认双侧）。无穷远写 `oo` 或 `-oo`。例如：

```yaml
spec:
  operation: limit
  expr: sin(3*x)/x
  variables: [x]
  limit_point: '0'
  limit_direction: '+-'
answer: '3'
```

- 隐函数题目前没有独立的核验操作。题干须明确局部分支与定义域，`spec` 可以对该分支的等价显函数求导；不得把一个分支的结果宣称为整条曲线处处成立。
- 级数反例、证明和文字解释题省略 `spec`，填写完整参考论证与 `rubric`，由模型评阅。不能用一个人为编码的数字冒充论证的标准答案。数值部分和不证明收敛或发散；`partial_sum` 是程序调用，不能写成不存在的 `operation`。
- 工具只核验 `spec` 与答案的一致性。题干和 `spec` 是否描述同一道题、定义域与分支是否完整、预测是否符合错因，以及解释题论证是否严谨，都须数学审校。

## 错因与策略的数学审校

每个错因描述一种可检验的错误规则，不能仅写“不会做”“粗心”或凭原题错答认定错因。“偶发失误”由系统以 `slip` 表示，不在错因库再建一条。

`recurs_in` 填该错误规则可能再次出现的知识点，不是所有后续章节的清单，也不代替 `prerequisites`。回溯函数复合依靠先修图；第九讲章前预检依靠链式错因中的 `recurs_in: [calc.ch9.multivar_chain, ...]`。只填写存在且数学上合理的知识点 ID。

策略卡表达教学原则、禁止的做法和可评分的解释要点，不规定固定的“先问 A、再讲 B、再做 C”流程。Agent 根据实际回答决定教学动作。

## 判别追问题的审核

```bash
cd backend
uv run python -m app.knowledge draft-probe calc.ch2.chain.miss_inner
```

模型按错因起草一道追问题，程序检查通过后导出到 `drafts/`。教师审核题目和各错因的预测答案；通过后把题目移入讲次文件，并在错因的 `probes` 中加上题目 ID。

审核时须确认：

1. 标准答案正确，题干与 `spec` 一致，题目足够短且考查目标未漂移。
2. 每个预测都能由对应错因规则推得；某错因在这道题上可以答对，不能为了区分而强造错答。
3. `check_distinct` 至少分出两组；每个拟诊断错因在整套追问中至少有一次预测不同于正确答案。单题不必区分所有候选。
4. 两个错因若给出相同预测，只能共同保留或排除，不能据此认定其中一个；必要时另选追问。
5. 种子验证题不能与原作业或已展示追问题重复；抗诱错题的目标错因预测必须不同于正确答案。
6. 普通验证会分别按维度选兜底题。为同一知识点准备至少一道覆盖其全部精修错因的抗诱错题，计算正确性和近迁移各用一道独立的题。

计算题按结果判分；若要核查学生是否用了指定方法，应另出要求写出关键步骤的解释题。题目指纹能识别常规变量改名，不能替代教师对换序等不同数学表述的查重。

本批 C2 的追问题与预测审校依据见 [C2 交付记录](deliveries/C2.md)。后续运行 `draft-probe` 会调用已配置的远程模型；修改过的草稿需要重新数学审校和入库检查。

## 入库检查

```bash
cd backend
uv run python -m app.knowledge check    # 只检查
uv run python -m app.knowledge ingest   # 检查通过后写入业务库
```

检查会逐条报告出错的文件、条目 ID 和原因，包括：格式错误、ID 重复、引用的知识点或错因不存在、先修关系成环、标准答案与程序重算的结果不一致、判别追问题没有区分度。入库只新增或更新内容，不会删除；文件里删掉的条目会在入库时提示，由开发人员处理。已经被学生作答或展示过的题目不能再修改题干、答案、预测、评分要点等内容，否则整批拒绝入库；需要修改时，请复制一份并换一个新的题目 ID。

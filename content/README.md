# 教学内容填写说明

本目录存放由数学教师编写的教学内容，格式是 YAML。系统的知识图谱、错因诊断、出题和验证都读取这里的内容。

| 路径 | 内容 |
|---|---|
| `lectures/01.yaml` 至 `lectures/12.yaml` | 每讲一个文件，已经按《高等数学目录》生成好全部 75 节的骨架 |
| `template.yaml` | 填写模板，以第二讲“多层复合函数求导”为例，每种条目都有一份示例 |
| `drafts/` | 模型起草、等待教师审核的判别追问题 |

## 讲次文件的结构

每个讲次文件有五部分，除 `lecture` 外都可以省略。ID 全书唯一，可以引用其他讲的内容。

| 部分 | 说明 |
|---|---|
| `sections` | 本讲的节：节号、标题、考研数学一/二/三标签（`math1`、`math2`、`math3`）。已按目录生成，一般不用改 |
| `points` | 知识点：ID、所在节、名称、先修知识点 `prerequisites`；`exam_tags` 省略时沿用所在节的标签 |
| `misconceptions` | 错因 |
| `strategies` | 策略卡 |
| `items` | 判别追问题和种子题 |

骨架为每节生成了一个知识点，ID 形如 `calc.ch3.s2`，先修关系为空。教师可以把一节拆成几个知识点、改名，并补充先修关系。两条精修路径（第 1→2→9 讲、第 4→5→10 讲）涉及的节已经细化，例如 `calc.ch2.chain_rule`、`calc.ch10.polar`。改动已被引用的知识点 ID 时，要同时改掉所有引用。

## 需要教师编写的内容

按《技术文档》第 6 节的要求：

| 内容 | 精修路径 | 其余知识点 |
|---|---|---|
| 错因 | 每个知识点 2 到 4 个：ID、描述、错因族、可能复发的知识点 `recurs_in`，以及 1 个典型错例 | 每节至少 1 个高频错因 |
| 判别追问题 | 由模型起草，教师审核 | 不需要准备 |
| 策略卡 | 按错因族编写：教学原则、禁用做法、解释题评分要点，不写逐步教学流程 | 按错因族复用 |
| 种子题 | 每个知识点 1 到 2 道，含结构化描述 `spec` | 每个知识点至少 1 道 |

教师只写模型做不准的部分：错因的界定、跨章节的复发关系和教学原则。追问题、讲解和练习题由模型当场生成，再由程序和核验工具把关。

## 公式写法

- 题干、标准答案、预测答案用 LaTeX，并用单引号括起来，如 `'6\sin(3x)\cos(3x)'`。
- 题目的结构化描述 `spec` 用 SymPy 语法，如 `sin(3*x)**2`，程序按它重新计算标准答案。`operation` 可以是 `expression`、`derivative`、`indefinite_integral`、`definite_integral`、`double_integral`；定积分和二重积分还要写积分限 `bounds`。

## 判别追问题的审核

```bash
cd backend
uv run python -m app.knowledge draft-probe calc.ch2.chain.miss_inner
```

模型按错因起草一道追问题，程序检查通过后导出到 `drafts/`。教师审核题目和各错因的预测答案；通过后把题目移入讲次文件，并在错因的 `probes` 中加上题目 ID。

## 入库检查

```bash
cd backend
uv run python -m app.knowledge check    # 只检查
uv run python -m app.knowledge ingest   # 检查通过后写入业务库
```

检查会逐条报告出错的文件、条目 ID 和原因，包括：格式错误、ID 重复、引用的知识点或错因不存在、先修关系成环、标准答案与程序重算的结果不一致、判别追问题没有区分度。入库只新增或更新内容，不会删除；文件里删掉的条目会在入库时提示，由开发人员处理。已经被学生作答或展示过的题目不能再修改题干、答案、预测等内容，否则整批拒绝入库；需要修改时，请复制一份并换一个新的题目 ID。

# T08 教学规划

`create_planner(engine=..., llm=..., knowledge=..., policy=...)` 实现现有 `Planner` 协议。
Agent 只读取业务数据并返回计划；任务、取消操作、转交状态及 SSE 均由编排层提交。
`create_app` 在配置 `LLM_API_KEY` 后自动接入，与验证 Agent 共享 T06 客户端；测试可以
通过 `orchestration_dependencies` 注入模型或 Agent。未配置模型时保留事件待办，不生成模拟结果。

## 决策与证据

程序从事件、目标、知识图谱、账本和历史任务发现合法候选，计算目标差距、先修阻塞、
截止日期和复发风险。模型为候选选择教学建议、课上讲解和先修回溯；程序强制执行
证据归属、先修路径、轮次、复测日期和任务去重。非法输出整份拒绝，事件保持未处理。
错误通过运行时 `wait_idle` 和日志暴露，修复模型或配置后可重新处理原事件。

作业的 `matched_misconception_id` 只是初步线索，不写成已确认假设，也不放进个体任务的
`misconception_ids`。只有同一错误事件的候选被排除到唯一 `SUPPORTED` 假设时才视为确诊。
共性建议在理由中标明初步或确认；初步聚类的错因单独存在私有任务上下文中。
`GET /api/class/issues` 从真实任务及其证据查询学生名单，不依赖演示数据中的预期数字。

- `PLANNER_CLASS_REVIEW_MIN_STUDENTS=3`：同知识点、同错因的人数阈值。建议集中讲解
  仍保留逐人诊断。诊断修订或学生掌握后，待执行的旧建议被取消或替换。
- `PLANNER_RETEST_DELAY_DAYS=3`：初步掌握后的最短复测间隔，按教学日历天计算；模型可以
  延后。初步掌握截止日期不截断延迟复测。保持通过后不循环安排复测。
- 作业正确但尚无掌握依据的学生收到独立验证任务，不凭作业正确宣称达标。
- 偶发失误按 T09/T03 的约定只做一道正确性独立验证，通过后结束本次任务，不自动追加
  无目标错因的完整验证。单题证据不足以满足 T19 的初步掌握门槛时保留账本原状态，
  不以补测、伪造错因或直接改状态来宣称达标；单题未通过仍按轮次重新规划。
- 一轮验证完成后才安排下一轮或转交；两轮上限取当前原目标的 `TeachingGoal.max_rounds`。
  未设目标时，不凭空设轮次上限或无限重开失败的辅导；无法判定的未建模错因仍可转教师。
- 先修回溯保存原目标与轮次，先创建单维正确性独立检查，而不是用原目标错答直接启动
  先修辅导。检查答错后，创建引用先修实际错答的辅导任务；检查通过后返回原目标。
  入口检查不消耗额外辅导轮次，先修干预仍使用原目标的轮次上限。无法判定时不创建
  缺少错误依据的诊断任务。转交附本轮及历史证据，由 T19 校验后迁移掌握状态。

## 编排与后续任务边界

`PlanningTaskContext` 是编排私有表，保存原目标、预检情境和初步聚类错因，不改变公共实体
或 OpenAPI。预检使用 `CROSS_CHAPTER`，重启后仍恢复后续知识点情境。
编排串行处理规划事件，并在落库时再次去重；节点回执保护事务成功而 checkpoint 尚未保存
时的重试。验证作答事件在任务到达下一等待点或完成后才入调度队列，避免最后一题和完成节点竞态。
进行中任务仅阻塞同一原目标或同一实际知识点的冲突规划，其他知识点的新作业仍创建任务；
模型调用期间学生启动任务时，落库阶段也按同一原目标/知识点规则判断冲突。

T08 消费 `LectureEntered` 并按三条规则创建预检，也兼容已由 T07 创建的预检，不重复创建；
日期推进和到期扫描仍由 T07 负责。两者复用账本的唯一确诊查询；编排启动预检时优先读取
T07 的 `PrecheckContext`，规划创建的任务则读取 `PlanningTaskContext`，保留到期派发和跨章情境。
T09 用现有 `REQUEST_REPLAN` 请求重规划：编排取消原任务并产生 `TaskDue`，T08 沿先修
选择下一步或转交。T15 主动提问、T16 教师处理和 T24 覆盖/接管仍由各任务实现。

## 验证

在 `backend` 使用项目隔离环境运行：

```sh
uv run pytest tests/test_planner.py -q
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m app.openapi --check
uv run python -m app.knowledge check
```

T20 的 40 人 CSV 经真实 T17/T19 导入验证 12 错；测试用受控的初步分析信号验证 8 人聚类，
不能从 A/B/C 相同的原答案强行确认其真实错因。测试模型替身不代表线上模型效果；
完整演示预跑仍依赖 T07、T09、T14、T16 等任务。

# T09 诊断辅导 Agent

入口为 `create_tutor(llm=..., knowledge=..., engine=..., tools=None, teaching_date=None)`，返回实现既有 `Tutor.turn()` 的 `DiagnosticTutor`。模型、数学工具、知识图谱及业务库由组合入口注入，客户端由调用方管理。配置模型密钥后应用默认装配 tutor 和 verifier，复用同一个模型客户端；显式传入实例或 `None` 分别覆盖对应依赖。

## 行为

- 根据错误证据检索目标知识点的已审核错因，模型提出至多两个内容候选，程序添加 `slip`。原题的预测中，若多个错因都匹配原始错误，首次诊断保留这些候选，不能仅凭原始同一错答确诊。
- 优先使用教师审核的追问题，按表达式由简到繁选择。每题预测完整覆盖当前有效候选；标准答案通过 `verify_item`，预测通过 `check_distinct`，且当前有效候选至少落在两个答案组中。程序按学生历史作答及题目曝光指纹去重。
- 无合适现成题时最多生成三次；生成题还独立审查题意、spec 和错因预测的一致性，失败原因用于下一次生成。随后选择未重复且通过同样数学门槛的种子题；无题可用则申请重规划。练习可使用验证种子题的副本，记为 practice，原题不变；曝光后独立验证会排除其指纹。
- 程序逐项比较答案与预测，允许同时支持多个假设；已排除的假设不在本批次恢复。解析失败时用模型补充未知结论，明确的工具结论保持权威。所有候选排除后重新提出候选，累计追问作答次数不清零；三轮仍不能确诊则申请重规划。
- 唯一支持的错因进入按策略卡的辅导。漏层使用分层拆解；公式代换使用原题的中心差商与原答斜率比较，再讲变化率。新练习只要求一个可核验的计算表达式，教学对话负责引导，不把上一题作答与新题混淆。
- 练习通过后申请独立验证；偶发失误直接申请一道正确性验证。连续两次练习未通过时，附允许的先修回溯路径请求重规划；达到教师目标轮次上限时请求转交教师。未建模错因保存为待审核内容，关联无法判定的证据及任务后请求教师处理。

## 持久化、事件与日期

私有表 `tutor_session` 保存阶段、候选批次、追问次数、策略和题目顺序，`tutor_receipt` 保存各阶段及完整回复。判定与假设、证据同事务提交，再调用模型出题；选定题目持久化后才流式生成辅导文字。网络等待期间不持有 SQLite 写锁。重启或节点重试复用已提交判定和选定题目，不重复追加证据或重新出题。

复用种子题时仅从业务字段构造新的 `Item`，不复制 SQLAlchemy 身份；每次辅导保存独立题目，教师原题及其预测、维度保持不变，供同一运行时的其他学生继续使用。

题目展示后登记曝光，回复等待题目 ID 沿用编排契约。假设及证据事务提交后发布 SSE 通知，通知可重复，前端按 ID 重新查询；辅导正文通过模型流逐段发布 `TokenDelta`，`MessageDone` 仍由编排在 checkpoint 保存后发布。

教学日期优先使用注入的时钟，否则使用编排私有上下文中的本次教学日期；直接调用时回退到任务创建日与原始错误日期的较晚者。异步上下文在辅导调用后重置，不增加 Agent 输入或 HTTP 字段。

诊断与练习证据直接追加到账本，受只追加触发器保护，辅导模块不调用掌握迁移。独立验证仍由 T18/T19 决定掌握状态。现有 T19 对 `slip` 的单道正确性验证只记通过证据，不据此进入要求三个维度的“初步掌握”。

## 接入边界与验收

`GET /api/tasks/{task_id}/diagnosis` 返回初始错误、全部候选及按顺序排列的追问，包括尚未作答时的预测；无诊断返回 404。沿用现有 contracts、OpenAPI 及前端类型。

T08 尚未实现，现有编排仍要求辅导任务注入 planner；T09 的完整链路测试使用确定性规划桩。真实自动重规划、回溯任务创建及转教师由 T08 接续，审核采纳由 T16 接续；本模块不会伪造这些产物。

未建模证据通过 `matched_misconception_id` 关联新建错因，并同时关联假设和任务；`is_correct=None`、假设保持待检验。T08 用该关联识别无法判定的未建模错因，即使没有教学目标也可生成转教师任务，由账本完成升级。

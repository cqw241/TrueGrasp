# 提交与视频并行开发计划

更新日期：2026-11-10。成员：柴、朱、吴。

本文件是团队从当前进度出发的执行计划。目标是尽快交付可公网访问的演示系统和 4–5 分钟讲解视频，展示五个教学场景。原 [开发计划](../开发计划.md) 保留完整需求和原任务验收标准；本文件中的分工和优先级适用于本次提交。

提交范围暂按需要公网链接、教师和学生演示账号编排。朱尽早核对主办方实际提交规则、截止时间和评审要求；若要求主动提问、教师接管或其他暂缓功能，调整本计划后再安排开发。

## 1. 当前基线

- `main` 上 T01–T12、T17–T20 已有合并记录，包含规划、辅导、验证、账本、教学时钟、学生辅导台和教师驾驶舱。T13 页面目前主要展示知识路径；教学目标、转交和主动提问等接口仍有未实现部分。
- C2 精修内容和 T20 演示输入已提供；C2 交付记录明确没有外部数学教师签审。40 人数据是合成输入，不是实际预跑结果；C3 全书内容和证据覆盖尚需核实。
- T07–T09 曾进行真实模型联合测试，发现的问题有定向回归证据；合并后的完整应用尚无端到端验收记录。不能用单项测试替代本次预跑。

## 2. 必须展示的场景

| 场景 | 演示内容 | 验收依据 |
|---|---|---|
| 主动发现 | 导入作业后展示教学目标、班级问题与课上或个别干预建议。 | 系统实际生成的任务、证据和驾驶舱数据。 |
| 可解释诊断 | A、B、C 相同错答，通过追问区分候选错因，展示预测与实际作答。 | 真实诊断记录与假设状态。 |
| 独立验证与跟进 | 展示 B 的验证、延迟复测、回溯和转交教师的证据链。 | 真实时间线、验证结果及转交任务。 |
| 跨章节与实时诊断 | 展示第 1→2→9 讲路径和第九讲预检，再由 D 现场作答第十讲极坐标题。 | 真实预检记录；D 作答后界面更新，快照恢复后可重做。 |
| 全班结果 | 驾驶舱展示班级达标情况、转交名单及 12 讲热力图。 | 按真实预跑结果展示；没有证据的格子显示未评估。 |

12 人出错、8 人同因、37 人达标、3 人转交、2 人复发是演示目标，须由真实运行结果核对，不能为了凑数直接写入掌握状态或伪造证据。详见 [演示输入和运行记录说明](../demo/README.md)。

## 4. 并行顺序和依赖

1. **同时开工。** 柴做 T13，并推进 T26；朱做 T16 目标与转交接口，同时准备部署；吴做 T14，同时准备视频讲稿。三人先约定学生 ID、目标创建方式、脚本入口、快照边界和接口；涉及 `contracts` 或 OpenAPI 变更先与柴确认。
2. **小规模贯通。** T14 基本操作和 T16 目标接口可用后，吴组织 A/B/C 及少量学生走通导入、诊断、独立验证与一次复测；柴核对证据展示，朱修复阻断问题。此阶段无需等待公网部署和完整登录功能。
3. **全班预跑。** 小规模链路通过后，吴运行 40 人数据和第九讲预检，记录结果与问题；朱修复阻断问题，柴修复展示问题。三人复核五个场景、真实统计和证据，保存业务库及 checkpoint 快照，并验证恢复后 D 的现场诊断可以重做。
4. **公网验证与正式录制。** 预跑快照、T13、T16 最小接口及 T26 可用后，朱部署提交版本并恢复快照；柴和朱检查教师、学生账号、接口权限和实时流；吴完成试录、正式视频和提交材料。记录提交版本及快照，确保视频和公网演示对应同一批真实预跑数据。

## 5. 暂缓范围与交付检查

- T15 主动提问、T24 教师接管与覆盖、T25 网页演示控制台暂缓；预跑先使用 T14 命令行。界面中暂缓功能应隐藏或明确标为未开放。
- 此处的预跑是**提交范围预跑**，不等于原计划的完整 T21；不要将 T15、T24、T25 或完整 T16、T21 标记为已完成，也不因缩范围验收触发原计划的 `demo-v1` 标签。记录实际提交版本和快照。
- 提交前检查：五个场景均有可展示的真实记录；快照恢复及 D 的实时诊断验证通过；教师与学生账号和公网链接可用；视频时长与提交格式符合主办方要求；问题和结果偏差已记录。
- 录制顺序：主动发现 → A/B/C 可解释诊断 → B 的验证与跟进 → 跨章节预检及 D 实时作答 → 全班结果。

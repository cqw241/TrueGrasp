## 本轮接入

持久化来源沿新建/复用任务、作答后规划和复测传播，查询按原事件班级过滤；失败持久化与回复受理继续保留。新增以下已鉴权接口，并同步 OpenAPI 与前端类型：

| 接口 | 行为 |
| --- | --- |
| `GET /api/homework-publications/{publication_id}/progress` | 同班来源任务、学生姓名/学号、知识点、当前掌握状态、各维最新独立验证结果与证据 ID，以及失败/接管/在班状态 |
| `POST /api/homework-publications/{publication_id}/workflow-retries` | 202 返回回执；只恢复已成功导入的原工作，不重复导入 |

两个入口核对教师角色、发布所属草稿和班级；其他教师返回 404，学生返回 403。任务接管状态也按任务班级查询。

## 1. 实现与接入

### 导入与发布共用一个事务

`HomeworkImporter.import_rows` 保留原有行为，新增三个关键字参数：

| 参数 | 用途 |
| --- | --- |
| `session` | 传入与导入器相同 Engine 的业务 Session。导入器仅写入/flush，不 commit、不关闭 Session；调用方负责一起提交发布回执、记录来源、幂等标记，异常时一起回滚 |
| `allow_new_students=False` | 网页发布使用已确认的稳定学生 ID，禁止沿用旧 CSV 的“凭姓名隐式创建学生”。未传时保留旧接口/CLI 行为 |
| `validate_before_write` | 所有模型调用完成、业务写入开始前，在同一 Session 里重新核对班级成员、确认版本和发布占用；校验失败抛异常，由调用方回滚 |

导入器额外复查学生是否在模型调用期间被删除或改名，不静默恢复已删除身份。正式证据仍由既有账本写入；作业事件仍只有一个 `HomeworkImported`，相应 `PendingWork` 与证据在同一事务里写入。返回的 `HomeworkImportResult` 及 HTTP 接口没有变化。

发布服务的接入顺序如下（调用方的权限、版本、幂等和回执写入由 OPT-01/04 实现）：

1. 先授权当前教师和班级，取得已确认版本、稳定学生/题目 ID；以数据库约束保护发布占用和幂等键。
2. 由调用方持有业务 Session，调用 `import_rows(..., session=session, allow_new_students=False, validate_before_write=...)`。
3. 在同一事务中读取返回事件的 `HomeworkImported.evidence_ids`，按输入行顺序建立记录—证据映射，写入发布成功回执和来源关联；最后只 commit 一次。失败则 rollback。
4. **提交成功后**调用现有 `runtime.recover_pending()`。唤醒失败不回退已提交的发布；持久化待办与重启恢复继续处理原事件。

本轮没有实现发布幂等键、草稿锁、班级授权或上传审核端点，也没有把 `evidence_writer` 回调当作完整发布事务。调用方必须完成上述步骤，不能直接从浏览器调用内部导入方法或以 `validate_before_write` 替代鉴权。

### 教学状态及来源

新增内部 `runtime.homework_workflow(event_id)`，以及复用业务 Session 的 `app.orchestration.workflow.homework_workflow(session, event_id)`。返回结构与 PR #38 的 `workflow` 设计衔接：

```json
{"event_id":2,"state":"planned","task_ids":[1,2],"error":null}
```

- `pending`：原作业或关联作答/到期事件尚未完成规划；缺少真实 Agent 时保留此状态。
- `planned`：规划已经提交，**不代表学生已完成任务或已掌握**。可能没有新增任务，也可能复用已有任务。
- `failed`：原事件、关联任务或作答后的后续规划存在未恢复的失败。保留已导入作业和进度，返回可供展示的简短恢复提示。

新增私有 `orchestration_event_task` 表记录实际新建、复用的任务，并传播后续复测等任务的来源。它不会改变现有任务创建、去重、教师接管或调度规则。旧事件仍可读取原规划节点回执中的任务 ID；不能事后猜测未记录的历史复用关系，因此旧作业的来源投影可能不完整。

新增私有 `orchestration_failure` 表，保存工作键、连续失败次数、异常类型和时间。异常正文、模型响应、学生原始内容和密钥不写入该表。即使换一个没有 Agent 的只读进程，也能辨认已有失败；学生端既有 `answer-target` 同时参考该持久化状态。

### 恢复原工作

新增内部 `await runtime.retry_homework(event_id)`，只恢复同一作业关联的原事件及失败任务，保留既有 dispatch 参数、checkpoint、已提交证据与节点回执。重复调用不会重新导入作业、创建第二个作业事件或重复提交成功节点。接管、任务结束/恢复和到期约束继续由既有运行时检查。

失败仍不会在监听循环中无限自动重试；显式恢复或服务重启后可继续执行，成功确认工作时清理失败摘要。该方法未新增公网 REST 重试接口，未来发布入口须先核对教师及班级授权。

普通辅导和独立验证作答也沿用主动提问已有的持久化受理机制：先保存原回复、教学日期和等待轮次，再启动后台图执行。这样即使在首个作答 checkpoint 前退出，重启仍可消费已经受理的回复；判分失败时原工作保持待处理并记录失败，恢复不要求学生重发答案。轮次校验和 checkpoint 共同防止把旧回复再次用于下一题，处理中重复提交仍返回 409。

## 2. 真实联调发现的阻断修复

概念性错误样例在独立验证出题时卡住。对测试进程的采样栈显示：`check_distinct → check_equivalent → _numeric → 定义域交集 → SymPy Diophantine`。同步符号计算占住事件循环，外层 150 秒的 asyncio 超时也无法及时触发；测试进程人工终止，保留业务库和 checkpoint。

本轮仅移除数值比较中两个定义域的符号交集：分别用各自定义域提供采样区间，再检查两个表达式在采样点是否均为有限实数。无有效样本仍返回不确定，不将其判成正确。保留原有采样次数与判定来源，不把数值采样称作严格证明。修复后从原检查点恢复成功，无需重新导入。

新增独立子进程中的周期定义域比较回归，20 秒超时会终止该测试，避免同类回归卡住测试进程。**这不是所有 SymPy 运算的通用超时机制**；其他符号计算的资源边界仍需单独处理，也不代表既有 R4 多会话风险已全面解决。

## 3. 真实模型记录

模型为 `deepseek-flash`，地址为 `https://api.deepseek.com`，凭据由用户指定的 T04 本地配置读取，不随代码提交。使用独立本地业务库、checkpoint、认证库和两个独立 Cookie 会话，通过实际教师/学生 API 访问应用；应用自动组装既有规划、辅导、验证 Agent。

这是**真实模型驱动的合成学生验收**，学生回复由另一模型调用仅根据学生可见的题面/消息生成，不读取内部答案。不是真实学生实验，不作为教学成效数据；未改动公网演示数据。

| 场景 | 实际结果 |
| --- | --- |
| 简单漏乘 | 作业 `sin(3x) → cos(3x)`；导入 1 条作业证据，自动分配辅导任务；学生完成辅导和一次独立验证，任务结束；验证正确性通过，掌握状态仍为 `tutoring`，未冒充多维掌握；用时 33.39 秒 |

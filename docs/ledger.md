# T19 掌握状态与证据查询

`app.ledger.service.append_evidence(session, evidence)` 在调用方事务中追加证据并推导掌握状态，不自行提交。作业导入与编排的独立验证共用此入口；辅导练习、诊断结论与教师说明不能直接证明掌握。数据库触发器阻止对证据进行 UPDATE 或 DELETE，包括绕过 ORM 的 SQL。

初步掌握要求同一学生、知识点及验证任务内的正确性、抗诱错以及近迁移或解释通过。复测通过后巩固，跨章验证通过后融会贯通；历史日期的证据追加保留，但不覆盖更新的状态。已确认错因再次命中时进入错因复现，后续辅导任务开始时进入辅导中。辅导开始与规划创建转交任务时，由编排程序调用状态机；模型不接收状态写入接口。

转交任务必须达到该知识点教学目标的轮次上限，或同时关联待审核错因及无法判定的证据。规划与状态迁移使用同一个事务。

查询沿用既有 HTTP 契约：学生名单、学生掌握状态、六维验证最新结果、证据详情、学习时间线、全班目标达成率与知识热力图。`app.ledger.queries` 也可直接被规划模块调用。没有目标时不推测达标人数；达标按最近目标中的全部知识点计算。

验收：在 `backend` 运行 `python -m pytest tests/test_ledger.py tests/test_orchestration.py -q`。测试覆盖每条迁移、教考分离、跨学生/任务隔离、证据不可变及调用方回滚。

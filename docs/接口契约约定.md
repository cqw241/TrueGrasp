## 1. 适用范围与现有系统

目标是衔接 OPT-01/02 的身份管理、OPT-03/04 的上传审核和 OPT-05 的教学闭环。优先复用现有实体与编排，只为草稿、来源、发布回执补充必要契约；不新增另一套任务系统。

| 现有机制 | 已核对行为 | 对本契约的影响 |
| --- | --- | --- |
| `backend/app/auth.py`、`api/auth.py` | 独立认证库；`Principal(username, role, student_id)`；Cookie `truegrasp_session`；写请求检查来源；教师当前直接放行 | 沿用登录及来源检查；班级权限是吴需补充的能力，不能把当前教师放行当成隔离已完成 |
| `contracts/entities.py` | `Student(id: str, name: str)`；没有班级、教师归属；`Task`、`Evidence`、`Event` 无 `class_id`；`Mastery` 主键为学生与知识点 | 保留现有学生 ID 和学习档案；新增作用域关系需明确迁移和传播 |
| `ingest/models.py`、`ingest/service.py` | `HomeworkRow`；CSV 必填学生 ID、题目 ID、作答；未知学生可凭姓名创建；新题必需题干和标准答案；每题一个主知识点 | 网页发布必须先匹配班内已有学生；题目不满足导入要求则继续留草稿，不自动创建学生 |
| `api/teacher.py` 的 `POST /api/homework` | multipart `file`，仅结构化 CSV；返回 `HomeworkImportResult`；422 输入错误、409 数据冲突、502 模型失败 | 保留集成入口；新审核发布入口直接复用导入服务，不在服务器内重新发 HTTP 或转存 CSV |
| `ingest/service.py` | 先模型分析再整批事务写入学生、题目、证据、账本派生状态、一个 `HomeworkImported` 和 `PendingWork`；内部自行 `commit()` | 当前没有发布回执、幂等键、班级归属或调用方事务参数；本契约的原子发布需要最小扩展 |
| `llm/vision.py`、`ingest/models.py` | 已有转写 `latex/doubts/requires_confirmation` 和图片 `ImageDraft`；CLI 无疑问时可直接导入 | 复用转写能力；教师新工作流始终先审核。旧图片草稿不能完整表达多学生、多题、来源及修改历史 |
| `orchestration/runtime.py`、`storage.py` | `PendingWork(event:<id>)`、节点回执、checkpoint 恢复；`_save_plan` 创建任务并做去重 | 任务只由朱负责的现有编排链路创建；柴只发布作业与唤醒待办 |
| `agents/planner/agent.py`、`queries.py`、`api/stream.py` | 作业事件按证据规划；共性问题、目标等仍有全局查询；教师 SSE 当前可见所有事件 | 仅在 HTTP 入口检查班级不够；吴、朱必须让查询、任务、附件及推送共同遵守作用域 |

特别说明：现有导入器每次调用都会追加证据，任务节点的去重不能代替发布幂等。`append_evidence` 可能把错误作业派生为“待干预”等状态，但不会因一次作业正确就宣布已掌握；本文不绕过账本规则。

### 1.1 通用约定

- 下文路径均为**拟新增**；现有路径在表中另行标注。JSON 使用 `snake_case`，所有 ID 对客户端均为不透明值；现有学生、题目 ID 为字符串，任务、证据、事件 ID 为整数，保持原类型。
- ISO 8601 UTC 时间戳用于上传和审计；`teaching_date` 为 `YYYY-MM-DD`，由发布时的现有教学时钟取得并冻结，未配置时沿用现有日期回退。客户端不能自行改教学日期。
- 沿用 Cookie 会话和 `check_origin`。身份、操作者、归属由服务端从会话和资源解析，不接受正文传入的教师身份作为授权依据。
- 新接口：401 未登录；403 角色不符或来源不允许；对象不存在或无权访问统一 404，避免暴露其他班级资源。校验失败 422，版本/状态/重复冲突 409，文件过大 413、格式不支持 415。保留现有接口的既有错误格式，不全局改写。
- 新接口业务错误用 `{"detail":{"code":"...","message":"...","retryable":false,"issues":[]}}`；`issues` 项为 `{record_id: string|null, field: string|null, message: string}`。框架自身字段校验仍可返回现有 FastAPI 422 列表，客户端需兼容。

## 2. 契约一：学生与班级身份关系（吴主责）

### 2.1 最小关系与稳定 ID

| 对象/关系 | 核心字段 | 约定 |
| --- | --- | --- |
| 教师身份映射 | `teacher_id: string`、`username: string` | 拟由 OPT-01 分配不可变教师 ID，关联现有认证账号；不新建登录体系。当前账号只有用户名，无此 ID；认证库与业务库分离，映射及迁移由吴确定 |
| 班级 | `class_id: string`、`name: string`、`teacher_id: string` | 班级 ID 不随名称变化；v0.1 提议一个班级一个负责教师，教师可有多个班级；暂不引入助教或共享管理角色 |
| 学生 | `student_id: string`、`name: string` | 对应 `Student.id/name`，旧 ID 原样保留；新 ID 由服务端生成，不用姓名、用户名或班内学号拼接 |
| 学生账号绑定 | `username: string`、`student_id: string` | 继续复用认证账号的 `student_id`；账号与入班关系分离，入班/退班不得重置密码或复制学习档案；初稿提议一个学生一个有效登录账号 |
| 班级成员 | `class_id`、`student_id`、`student_number: string|null`、`status: active/left` | 班内学号只作身份线索；非空时班内唯一。成员关系退班后保留，不删除学生、证据和任务 |
| 业务来源作用域 | `class_id`、资源 ID、来源关联 | 草稿、文件、发布属于班级；正式事件、证据、任务也必须能反查班级。物理上用字段或关联表由吴决定，不强制重建所有实体 |

**[A 待确认，吴提交方案]** A 为本轮需求指定的设计确认方，具体人选尚未在仓库资料中确定，不与学生 ID `A` 或计划中的阶段 A 混用。吴负责汇总以下设计供 A 确认：

1. 教师稳定 ID 与认证库映射；是否接受首期单负责教师及一个学生一个有效账号。
2. 首期提议学生仅有一个有效班级，可退班再入班而保留全局学生 ID。若需同时加入多个班级，必须先确认全局 `Mastery(student_id, knowledge_point_id)`、全局教学目标/时钟及跨班证据的使用边界，不能仅增加多对多关系就视为兼容。
3. 旧学生、证据、任务、教学目标和章前预检的作用域迁移。不能判断的旧数据先保留为“未分配”，通过维护操作显式关联，不默认向所有教师授权；不新增管理员登录角色。
4. 转班后的历史可见范围与未完成任务处理。初稿提议历史保留原班级来源，原班教师可看原班历史，新班教师仅看新班记录；退出后停止旧班任务继续派发。跨班调用学习档案的内部策略由吴、朱确认，不能从全局时间线/掌握状态向新教师泄露旧班详情。

这些项在确认前都是建议，不是已定数据模型。OPT-03 只依赖稳定 `class_id/student_id` 与统一授权能力，不自行落地身份表。

### 2.2 归属与权限边界

- 教师能管理其负责班级的名单、草稿、原文件、发布、任务、证据与统计；`created_by_teacher_id` 仅为审计，权限按班级归属判断。教师取得某学生当前班级权限，不等于取得该学生其他班级历史权限。
- 学生只读本人正式任务与允许公开的学习记录；不能访问班级上传草稿、教师参考答案、同学信息或整批原文件。包含多人作答的 PDF 不直接向学生开放，后续若需展示本人原图，须按本人记录裁剪并单独授权。
- `class_id` 与资源不一致、学生不在班内、成员已退出：拒绝修改/发布；不得让 CSV 内的学生 ID 或模型姓名推断自动建档/入班。
- 来源作用域沿 `发布 → 作业事件 → 证据 → 规划任务 → 后续辅导/验证/复测/转交` 传播，班级讲解任务即使 `student_id=null` 也必须有作用域；共享知识点目录可继续全局使用，上传产生的题目/参考答案不因此自动公开。
- 旧 CSV API、学生/任务列表、时间线、统计、SSE、附件读取和 Agent 全局检索同样接入授权与作用域；不能用旧接口旁路上传审核的归属限制。`teacher_has_student` 当前表示教师接管，不是班级授权函数，不能复用为归属判断。

### 2.3 供上传工作台依赖的身份 API（拟定，吴确认）

| 方法与路径 | 请求/返回核心内容 |
| --- | --- |
| `POST /api/classes` | `{name}` → 201 `{class_id, name, teacher_id}`；教师身份由会话取得 |
| `GET /api/classes` | 无正文 → 200 `[{class_id, name, teacher_id}]`，仅本人可管理班级 |
| `GET /api/classes/{class_id}/students` | 无正文 → 200 `[{student_id, name, student_number, status}]`；仅返回该班成员，默认有效成员 |
| `POST /api/classes/{class_id}/students` | 关联已有学生 `{student_id, student_number}`，或新建 `{name, student_number}`，两种互斥；201 成员及稳定学生 ID |
| `DELETE /api/classes/{class_id}/students/{student_id}` | 无正文 → 204，退出而非删除；重复退出仍 204 |

关联已有学生需先校验该身份可被当前教师关联；不能只因知道一个全局 ID 就读取姓名或把他人学生拉入班级。未知 ID 或不可关联身份 404；重复成员、学号冲突、另一有效班级冲突 409，不改原账号。新建/发放登录凭据的完整流程由 OPT-02 定义，本契约响应不包含密码或哈希。

示例（关联已有学生；ID 均为示意）：

```http
POST /api/classes/cls_01/students
Content-Type: application/json

{"student_id":"S01","student_number":"20260001"}
```

```json
{
  "class_id": "cls_01",
  "student_id": "S01",
  "name": "张同学",
  "student_number": "20260001",
  "status": "active"
}
```

身份识别接口只拿该班有效名单：不以用户名代替 `student_id`，不对全系统学生做姓名搜索。

## 3. 契约二：AI 作业解析结果格式（柴主责）

### 3.1 上传、读取与审核入口（拟定）

| 方法与路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `POST /api/classes/{class_id}/homework-drafts` | multipart：`files[]`（CSV/JPEG/PNG/WebP/PDF）、`title?`、`prompt_text?`；文件或文本至少一项 | 202 `{draft_id, class_id, revision, status:"parsing"}`；只接受并保存解析工作，不代表识别成功 |
| `GET /api/homework-drafts/{draft_id}` | 无正文 | 200 完整草稿，解析过程中允许已有结果与局部错误共存 |
| `PATCH /api/homework-drafts/{draft_id}` | `{expected_revision, question_updates?, record_updates?}`，各更新项带稳定 ID | 200 新版草稿；服务端保存修改历史并使 `revision + 1`；409 表示需刷新后再改 |
| `POST /api/homework-drafts/{draft_id}/parse-retries` | `{expected_revision, source_ids}` | 202 草稿标识；仅重试失败来源，不覆盖教师已编辑/确认字段；新识别作为候选供核对 |
| `POST /api/homework-drafts/{draft_id}/sources` | multipart：`files[]`、`expected_revision` | 202 草稿标识；补图/补页，保留旧来源和原版本 |
| `GET /api/homework-drafts/{draft_id}/sources/{source_id}` | 无正文 | 经班级授权后返回文件内容；不接收任意本地路径或外部 URL |

上传重试约定：创建草稿携带 `Idempotency-Key`，同教师、班级、同键及相同文本/文件摘要重试返回同一草稿；同键不同内容 409。不同键重复上传不做跨作业自动合并。解析/重试与修改在每次写回时检查版本，不用迟到的模型结果覆盖人工内容。

上传首先校验格式、实际文件内容、班级权限及资源限额。CSV 结构化兼容路径复用 `parse_csv`（10 MiB/5000 行）；新上传可接受非内部表头的可识别 CSV，由解析层转成草稿而不是立即调用导入器。图片限额优先沿用现有单图 8 MiB、2400 万像素限制；PDF 页数、总文件大小、批次文件数及解析调用预算由柴在实现前确定并可配置，不把它们写成当前已有能力。超限明确返回 413，不能静默截断页面；首期不承诺所有 PDF 都能提取。

### 3.2 草稿结构

| 结构 | 核心字段与约束 |
| --- | --- |
| `HomeworkDraft` | `schema_version:"0.1"`、`draft_id`、`class_id`、`created_by_teacher_id`、`title`、`revision:int`、`status`、`sources[]`、`questions[]`、`records[]`、`parse_errors[]`、`edits[]`、`created_at/updated_at` |
| `Source` | `source_id`、`kind:file/text`、`filename/mime_type/size_bytes/sha256`（文件）、`text`（直接输入）、`page_count:int|null`；文件由服务端保存，通过受控接口取回，摘要仅标识来源不替代发布幂等 |
| `SourceRef` | `source_id`、`page:int|null`（PDF 从 1 开始）、`row:int|null`（CSV 含表头的行号）、`region:[x,y,width,height]|null`（相对页面 0～1） |
| `Question` | `question_id`（草稿内稳定）、`number:string|null`、`item_id:string|null`、`stem:string|null`、`correct_answer:string|null`、`rubric:string[]`、`knowledge_point_id:string|null`、`knowledge_candidates:[{id,reason}]`、`source_refs[]`、`issues[]` |
| `Record` | `record_id`（草稿内稳定，一名学生一道题的一次作答）、`question_id`、`identity`、`student_answer:string|null`、`answer_kind:expression/steps/text/proof/mixed/unknown`、`source_refs[]`、`issues[]`、`review_status:pending/confirmed/skipped/published`、`publication_id:string|null` |
| `IdentityMatch` | `observed_name/student_number:string|null`、`candidate_student_ids:string[]`、`student_id:string|null`、`status:unmatched/ambiguous/proposed/confirmed`；候选只能来自该班；模型提议只能为 `proposed`，教师确认后才为 `confirmed` |
| `Issue` | `issue_id`、`field`、`code`、`message`、`blocking:bool`、`source_refs[]`、`resolution:null|{action:corrected/accepted,note,by_teacher_id,at}`；未解决阻塞项不能确认 |
| `ParseError` | `source_id`、`page:int|null`、`code`、`message`、`retryable:bool`；用于超时、页面无法读取等技术失败，不冒充模型疑点 |
| `Edit` | `revision`、`target_id`、`field`、`before`、`after`、`by_teacher_id`、`at`、`note:string|null`；由服务端记录，客户端不能伪造审计身份 |

语义约定：

- 原文件/原文本、首次 AI 提取版本、人工变更和发布确认快照分别保留。`questions/records` 表示当前工作版本，不覆盖首次 AI 版本；该原始版本与当前结构相同，由草稿详情的 `original_extraction:{questions,records}` 返回（首次提取结束后固定）。后续重试候选另存来源，不改该快照。
- 数学公式与文字均用可展示字符串，公式用 LaTeX；保留学生原步骤与错误，不替学生改正。看不清时为 `null` 或忠实保留可读部分并挂疑点，不能编造公式。`student_answer` 可含换行及证明文字，不要求通过 SymPy 才能保存/审核。
- 一个草稿题目对应一个主要 `knowledge_point_id`，与现有 `Item` 兼容；可保留多个知识点候选，但发布时只选一个已入库主知识点。`pending.unclassified` 被当前导入器排除，不能用作网页发布的主知识点。
- 复用已有 `item_id` 时从现有题目补齐题干、标准答案、主知识点，并检查归属/可用性；不覆盖原题。新题发布前需完整题干、标准答案和主知识点。证明题允许 `spec=null`；`rubric` 先保留草稿，但现有 `HomeworkRow` 无 rubric 字段，若朱需要把它写入新 `Item.rubric`，须确认最小导入扩展，不能声称已生效。
- 缺标准答案、无匹配知识点、纯题目尚无作答可以保存和继续编辑，暂不能走本契约的正式作答发布；不使用空字符串充当标准答案或作答。它们的开放式教学能力不等同于现有作业导入支持。
- 参考答案可由 AI 提议，但要注明疑点/来源并经教师确认；确认一条作答同时表示确认其引用题目的当前题干、参考答案和主知识点。草稿不携带可写入正式账本的 `is_correct`、确诊错因或掌握标签，正式判定交现有导入及 Agent。
- 题目共享字段被修改时，该题下未发布的已确认作答重置为 `pending`；学生绑定、作答和来源变化也撤销该记录确认。确认可批量执行，但每项仍需满足同样的关键约束。已发布记录及对应题目快照不可修改；仍待审核的记录若要改动已被发布引用的题目，须复制成新的草稿题再关联。
- 跳过记录保留原始数据与原因（以编辑备注记录），可重新改为 `pending`；不写正式证据。允许只发布部分已确认记录，其他项继续保留草稿。

### 3.3 示例：识别身份与公式均有疑点

下例省略来源摘要、时间戳及 `original_extraction` 等不影响阅读的字段；完整响应使用上表结构。

```json
{
  "schema_version": "0.1",
  "draft_id": "draft_01",
  "class_id": "cls_01",
  "created_by_teacher_id": "tch_01",
  "title": "链式法则作业",
  "revision": 1,
  "status": "review",
```

### 3.4 状态与异常

草稿 `parsing → review → published`；全部来源技术失败且无可审核结果时为 `parse_failed`，补图/重试可回到 `parsing`。部分技术失败仍为 `review`，保留成功记录与 `parse_errors`。`published` 表示已有发布且全部剩余记录为已发布或明确跳过；若还有待审记录，草稿仍为 `review`。进行解析时允许读取，暂不允许确认发布。

模型不确定性放 `issues`，不记为系统失败，也不自动更换学生；技术失败放 `parse_errors` 并提供补图/重试。只重试失败页，不丢弃成功页。某页失败未影响所选记录时允许发布其他完整记录；若它可能是所选题目缺失的条件/作答续页，则属于阻塞疑点，须补齐或跳过该记录。

## 4. 契约三：作业确认发布接口（柴、朱共定）

### 4.1 预览、发布与查询（拟定）

| 方法与路径 | 约定 |
| --- | --- |
| `POST /api/homework-drafts/{draft_id}/publish-preview` | `{expected_revision, record_ids}` → 200 计数、待解决问题及 `can_publish`；无业务写入，不调用导入器或 Agent |
| `POST /api/homework-drafts/{draft_id}/publish` | Header `Idempotency-Key`；正文 `{expected_revision, record_ids}`；首期同步执行导入，成功提交后 201 发布回执，随后异步规划 |
| `GET /api/homework-publications/{publication_id}` | 200 发布回执及最新编排状态；只读，不自动重发作业事件 |

`record_ids` 是非空、去重集合，只选择尚未发布且已确认记录；同一学生同一道题在该次发布只能有一条。服务端取草稿内容，不接受客户端再传一份“最终作答”绕过审核。发布前重新校验班级授权、有效成员、来源、版本和题目一致性；模型分析期间可能发生退班/改归属，提交业务事务前须再次校验授权及版本。

发布回执核心字段：`publication_id/draft_id/class_id`、`confirmed_revision`、`record_ids`、`confirmed_by_teacher_id`、`confirmed_at`、`teaching_date`、`status`、`import_result`、`record_results`、`workflow`、`error`。确认者及时间由服务端写入；`publishing/failed` 时 `import_result=null`、`record_results=[]`。错误对象为 `{code,message,retryable}` 或 `null`；编排错误单独放在 `workflow.error`。确认快照属于发布记录，不随草稿后续修订变化。

预览示例：

`students/items/answers` 分别按选中记录的学生、最终题目映射及作答计数；`items` 不是新增题库数量。`remaining_records` 为未选且尚未发布/跳过的作答数，不表示文件每页均已成功解析；局部失败与遗漏另在草稿中展示。预览不预留资格，发布仍以同版本重新校验；有待解决问题时预览返回 200、`can_publish:false` 和问题列表。

### 4.2 确认版本映射到现有导入

柴的发布入口把教师确认快照转换成 `HomeworkRow`，交给现有 `HomeworkImporter.import_rows(rows, teaching_date)` 对应逻辑：

| 草稿字段 | 现有导入字段/行为 |
| --- | --- |
| `record.identity.student_id` | `student_id`；必须是吴提供的班内有效学生，不走导入器“未知学生自动创建”路径 |
| 班内学生当前规范姓名 | 可不传 `student_name`，或传当前 `Student.name`；不能用 OCR 姓名覆盖已有学生 |
| `question.item_id` | 沿用可访问已有题目；新题由服务端按草稿题稳定生成，如 `hw.<draft_id>.<question_id>`，重试不得换 ID；同题各学生共用同一 ID |
| `question.stem/correct_answer/knowledge_point_id` | `stem/correct_answer/knowledge_point_id`；已有题内容不可原地覆盖；需改题时生成新的草稿题及新题 ID |
| `record.student_answer` | `student_answer`，保留确认后的完整作答字符串，不使用标准答案替换 |
| 原始文件、页码、疑点、修改、确认者、班级 | 不塞进 `HomeworkRow`（`extra=forbid`）；通过发布与记录/证据的来源关联保存并授权 |

现有导入器仍会调用模型做 `HomeworkAnalysis` 并按已有工具规则判定，保留“不确定”及初步错因语义；不直接把草稿建议当成正式判分。草稿确认的是身份和题目/作答输入，导入分析不得悄悄改写这些输入。`ItemSpec` 非必填，不额外要求所有证明/文字题数学结构化。

### 4.3 单一任务创建链路与职责边界

```text
柴：上传 → AI 草稿 → 教师审核 → publish 入口 → 确认快照/幂等校验
                               ↓
共定导入边界：复用 HomeworkImporter → append_evidence
            → HomeworkImported(knowledge_point_ids, evidence_ids)
            → PendingWork("event:<event_id>", {"dispatch": true})
            → 发布回执/记录来源关联与上述业务写入一起提交
                               ↓
朱：runtime.recover_pending() → handle_event(event_id)
    → 现有规划 Agent / _save_plan → Task / task 待办
    → 现有辅导、验证、证据账本、教师反馈
```

- **柴负责发布入口和导入适配；朱负责消费作业事件、规划及其恢复。两边不分别创建辅导任务。** 柴不写 `Task`，不再调用“给每名学生创建任务”；朱不为同一次发布再次导入、不再生成第二个 `HomeworkImported`。
- `HomeworkImported` 继续使用现有 payload；班级来源可用事件关联保存，不为班级边界复制另一种作业事件。事件的 `student_id` 可继续为空，不能凭空给它填某个学生充当班级。
- 任务数不承诺等于作答数：现有流程可能辅导、验证、复测、建议集体讲解，也可能复用已有任务；没有真实证据不能宣称“已确诊/已掌握”。
- 朱与吴共同限定规划输入、全局目标/历史检索、共性分组、已有任务匹配与取消范围，给新任务和后续事件传播班级来源。仅给新事件加 `class_id` 而保留全局查询不能满足隔离要求。

### 4.4 发布幂等与事务边界

以下是**待实现要求**，当前导入器尚不支持；不能把调用现有方法再单独写回执描述为原子发布。

1. `Idempotency-Key` 在同一教师身份内唯一，关联 `draft_id + expected_revision + 排序后的 record_ids + 确认内容摘要`。服务端先查已有键，再校验当前草稿版本，以支持成功后版本已变化的重放；仍须校验当前访问权限。
2. 首次请求持久化发布占用与确认快照，置 `publishing`，锁定选中记录及其题目内容；同一草稿首期只允许一个发布执行。相同键、相同内容执行中返回 202 同一回执；成功重放返回 200 同一结果，不再次模型分析/写证据。相同键不同请求返回 409 `idempotency_conflict`。
3. 换一个键重复发布已发布记录返回 409 `already_published`；与正在发布的记录竞争返回 409 `publish_in_progress`。数据库唯一约束必须保护“一个草稿记录最多一次成功发布”，不能只靠前端按钮禁用或进程内锁。
4. **共定最小扩展缝隙：** 保留 `import_rows` 现有对外行为，内部允许复用相同导入逻辑、由调用方持有 Session/提交事务（具体签名由柴、朱确认）。发布服务持有最终事务，把证据、题目、账本派生状态、事件、待办、班级来源、记录到证据映射、成功回执和记录已发布标记一次提交。不要复制一份导入算法，也不能只靠现有 `evidence_writer` 回调冒充完整发布事务钩子。
5. 导入模型调用前可持久化占用，正式业务写入仍整批原子。已有学生须在事务内再次验证，避免导入器在退班/删除竞争后隐式创建学生；题目内容和成员版本变化时回滚并报告冲突。
6. 成功提交后才调用 `runtime.recover_pending()`。唤醒调用失败也不能把已提交发布标为“未导入”；已有持久化待办、监听及重启恢复负责后续处理。幂等回执与证据共同提交，覆盖“提交成功但响应丢失/进程退出”的窗口。
7. 幂等及发布映射随作业保留，不设置短期过期后可再次发布的窗口；不同草稿上传了相同文件不自动判作同一份教学作业，跨草稿重复检测暂不承诺。

### 4.5 状态流转、失败恢复与异常

发布状态与教学编排状态分开：

| 状态 | 含义及恢复 |
| --- | --- |
| `publishing` | 已占用/锁定，正在模型分析或事务提交；成功进入 `published`，确定未提交则为 `failed` |
| `failed` | 正式导入整批未提交，记录仍可审核；回执保留错误，同键重放同一失败响应。修正后用新键重试；不复用旧键对应另一份内容 |
| `published` | 正式证据、事件、待办及回执已原子提交；不能因 Agent 失败回退或再次导入 |
| `workflow.state=pending` | 事件尚未完成规划，或缺少真实 Agent；不伪造空任务为“教学成功” |
| `workflow.state=planned` | 规划提交完成，可按现有事件节点回执展示关联任务 ID；不表示学生已完成辅导/验证 |
| `workflow.state=failed` | 后台失败待恢复，展示可操作原因；保留发布及证据，朱恢复原事件/任务，不补建任务 |

首期不加单独的发布队列或教学状态机。服务重启时扫描遗留 `publishing`：若有已提交成功回执则直接返回；确认旧执行者已结束且无原子提交时，标记失败、释放占用，允许新键重试。不能在旧请求仍执行时仅凭超时释放占用。所有发布字段编辑和状态变更采用版本/条件写，避免迟到响应覆盖结果。

`workflow` 是状态投影，朱负责提供真实来源。当前 `Event.processed` 和节点回执能确认规划已提交，但失败集合主要在内存中；可靠错误状态/查询和恢复入口的最小补充需朱确认。不能把“事件未处理”一律解释为失败，也不能仅 `recover_pending()` 就宣称失败工作已重试：当前 `_failed_work` 会阻止同进程自动重试，应由朱显式恢复原 `handle_event`/`start_task` 或采用现有重启恢复；不在本稿另建公开重试 API。

| 条件 | HTTP / code | 处理 |
| --- | --- | --- |
| 未确认、缺身份/题干/答案/主知识点、空作答、阻塞疑点、重复学生题目组合 | 422 `review_incomplete` | 返回逐记录问题；所选批次均未导入，允许修正或缩小选择 |
| 版本变化、成员退班、题目内容冲突 | 409 `revision_conflict` / `membership_changed` / `item_conflict` | 不提交；刷新重审；无权限对象仍按 404 |
| 幂等键缺失 | 422 `idempotency_key_required` | 不占用、不导入 |
| 模型分析失败 | 502 `import_model_failed` | 确定整批未提交时标记失败，保留草稿及确认快照；可新键重试 |
| 数据库约束冲突 | 409 `import_conflict` | 整批回滚，不留证据/事件/待办；返回冲突提示 |
| 数据库暂不可用 | 503 `storage_unavailable` | 先查回执确认提交结果；不能确定时返回带 `publication_id` 的错误并提示查询，不能让客户端盲目重发新作业 |
| 响应丢失、重复点击 | 同键 200 或 202 | 返回同一发布；禁止再次导入 |
| 发布成功后规划/辅导失败 | 查询 200，发布仍 `published`，`workflow.state=failed` | 展示教学待恢复；只恢复原编排工作，不重复证据或任务 |

错误示例（所选记录尚未确认）：

```json
{
  "detail": {
    "code": "review_incomplete",
    "message": "请先确认学生身份",
    "retryable": false,
    "issues": [{"record_id":"rec_01","field":"identity.student_id","message":"班内存在同名学生，尚未选择稳定学生 ID"}]
  }
}
```

已发布后的纠错不修改/删除证据账本，也不直接复用原记录再次发布；通过后续独立的更正流程追加记录，详细接口不在 v0.1 范围内。

## 7. OPT-03 首期实施说明（教师个人草稿）

OPT-01/02 尚未提供班级身份。按用户确认，本期不自建班级体系、不调用全系统学生名单匹配姓名，先交付教师个人草稿；不实施 OPT-04 的修改、确认或发布，也不创建正式题目、证据、事件或辅导任务。

### 实际接口

| 路径 | 当前行为 |
| --- | --- |
| `POST /api/homework-drafts` | multipart `files`（重复字段）、`title?`、`prompt_text?`；必需 `Idempotency-Key`；202 返回草稿并开始后台解析，同键同内容返回原草稿，不重新解析 |
| `GET /api/homework-drafts` | 当前教师的草稿摘要，按更新时间倒序 |
| `GET /api/homework-drafts/{draft_id}` | 完整草稿，解析期间可轮询；完成后 `review` 或 `parse_failed` |
| `GET /api/homework-drafts/{draft_id}/sources/{source_id}` | 当前教师授权后取原材料；图片/PDF 可查看，CSV/文字可下载 |
| `POST /api/homework-drafts/{draft_id}/parse-retries` | JSON `{expected_revision, source_ids}`；只重新处理所选失败页，保留成功页及其稳定记录 ID |
| `POST /api/homework-drafts/{draft_id}/sources` | multipart `files`、`expected_revision`，补图/补页；只解析新来源，旧原件及首次提取快照保留 |

沿用现有 Cookie 和来源检查；学生 403、其他教师读取/重试/补图 404。身份归属暂用现有不可改名的账号主键，返回 `created_by_username`，`class_id=null`；不把用户名伪装成契约拟定的稳定教师 ID。未来由 OPT-01 提供稳定映射再迁移这些草稿，不自动授权给其他教师。

`sources/questions/records/parse_errors/original_extraction` 沿用草稿核心结构；首次提取后固定 `original_extraction`，重试结果补入工作版本。原始文字作为一个来源保存，补充文字也交给同批文件的模型作理解背景。来源引用首期精确到文件、PDF 页或结构化 CSV 记录行，不生成模型猜测的框坐标。疑点首期为 `{code,field,message,blocking}`，人工处理及审计字段待 OPT-04 接入。

所有学生身份均为 `unmatched`，`student_id=null`、候选列表为空；CSV 中的学生 ID 另存为 `observed_student_id`，与姓名、学号同属待核对线索。有效知识点可提出建议，未知 ID 留空并标记疑点，不新增知识点。标准答案仅提取原材料提供的内容，不在解析阶段解题/判分；题干、答案缺失或只有题目没有作答也可保存。

### 资源、持久化与恢复

- 使用现有业务库新增两张表：草稿 JSON 与原始材料 BLOB；旧表不改。启动时 `create_all` 建表，部署后执行 `uv sync --locked` 安装新增 PDF 渲染依赖 `pypdfium2`。不新增对象存储或队列服务。
- 每份草稿最多 6 个文件、30 MiB；单图 8 MiB/2400 万像素、CSV 10 MiB/5000 行、单 PDF 20 MiB/12 页；最多 24 个解析单元和 5000 条作答。普通 CSV/直接文字最多 60000 字符；超限明确报错，不截断原始内容。模型调用复用现有超时、结构化校验和重试配置，逐页处理，不另加多 Agent 审核层。
- 标准内部 CSV 用 `parse_csv` 忠实展开，不为 OCR 重跑模型；其他 UTF-8 CSV/文字由文本模型提取，图片与 PDF 页面交视觉模型。PDF 渲染逐页缩放并串行保护 PDFium 调用，不宣称支持所有 PDF。
- 后台解析按页保存成功结果。模型故障/页面读取失败进入 `parse_errors`；不确定识别进入 `issues`。服务中断后，重启将遗留解析标为可重试并保留成功页；不建设自动无限恢复队列。
- `revision` 与条件写阻止同一草稿并发重试/补图。源文件与草稿一起提交；重复上传键在数据库唯一约束保护下不会创建两份草稿。此幂等仅用于个人草稿创建，不代表第 4 节正式发布已实现。

### 检查范围

定向检查覆盖多格式解析、原作答/疑点保留、个人授权、同键重放、PDF 部分失败后只重试失败页、补图、重启恢复以及不写正式题库/证据/任务；与现有认证检查合计 17 项通过。前端类型同步、构建、lint/格式及后端静态检查通过。在隔离数据库中通过教师网页调用真实文本模型，成功提取一题一份作答，保留学生的 `cos(3x)` 而未替换为参考答案 `3cos(3x)`；390px 窄屏展开草稿可正常阅读。图片/PDF 解析使用可控模型响应验证流程，不把它当作真实手写识别准确率验收。


## 8. OPT-04 实施说明：审核与确认发布

基于 `main@c9da806`（OPT-01/02/03 已合入）实现本节。本节覆盖前文仍标注为拟定、以及第 7 节个人草稿阶段的相关边界；不代表 OPT-05 的完整辅导、验证和教师反馈已验收。

### 班级、编辑与兼容

- 继续使用 `POST /api/homework-drafts`，multipart 新增可选 `class_id`；不另加重复的班级路径。网页上传传入驾驶舱当前班级。`GET /api/homework-drafts?class_id=...` 返回该班草稿及本人尚未绑定的个人草稿，供明确认领；不混入其他班。
- 已绑定草稿、文件及发布回执按 `Classroom.teacher_id` 授权；未绑定草稿仍仅原 `created_by_username` 可读。新草稿记录现有稳定 `created_by_teacher_id`。旧个人草稿通过 PATCH 明确绑定自己的班级，绑定后不可切换；不自动按姓名推断所属班级。
- 学生建议只用班内有效名单，按材料中的学生 ID、学号、姓名依次精确匹配，状态为 `proposed/ambiguous/unmatched`，教师标记已核对后才为 `confirmed`。发布重新检查有效成员，不创建学生。
- `PATCH /api/homework-drafts/{draft_id}` 请求为 `{expected_revision,class_id?,question_updates?,record_updates?,issue_resolutions?}`；所有更新项带稳定 ID，不能修改来源或伪造审核身份。题目更新支持 `stem/correct_answer/knowledge_point_id/item_id`；作答更新支持 `student_id/student_answer/review_status/note`。疑点处理项为 `{issue_id,action:"accepted"|"corrected",note?}`。
- 保存允许字段不完整；“已核对”必须满足有效身份、题干、参考答案、知识点、原作答及疑点处理要求。补齐缺失字段或修正对应识别字段时自动记录疑点解决；其余识别疑点须明确核对。数学字符串不额外要求 SymPy 可解析。
- 题目变更撤销该题未发布记录的核对，作答/身份变化撤销该记录核对。跳过保留原件和修改记录，可回到待核对。不做独立审计页面。
- 复用已有题目时不可修改原题；网页可清除关联、按新草稿题发布。已被发布引用的题目只读，首期不提供复制草稿题的 UI；需要变更该题时另建作业草稿，其他未发布记录仍可审核。补图和失败页重试只追加提取，不覆盖已编辑或已发布字段。
- 原件与 `original_extraction` 保留；`edits` 含前后值、版本、稳定教师 ID、时间及备注。发布回执增加 `confirmed_snapshot:{questions,records}`，使最终确认内容可直接追溯。`rubric` 仍只保留在草稿，不声称已传入正式 Item。

PATCH 示例（ID 取自草稿及本班名单）：

```json
{
  "expected_revision": 2,
  "question_updates": [{"question_id":"q_01","correct_answer":"3cos(3x)","knowledge_point_id":"kp.chain"}],
  "record_updates": [{"record_id":"rec_01","student_id":"stu_01","student_answer":"cos(3x)","review_status":"confirmed"}],
  "issue_resolutions": [{"issue_id":"issue_01","action":"accepted","note":"已对照原件核对"}]
}
```

### 发布接口与单一导入链路

- 实现第 4 节的 `publish-preview`、`publish` 及 `GET /api/homework-publications/{publication_id}`。正文继续使用 `{expected_revision,record_ids}`，publish 必须有 `Idempotency-Key`。预览无业务写入；导入同步完成后首次 201，同键执行中 202，成功重放 200，并返回 Location。
- 使用新增 `homework_publication` 表保存发布占用、请求指纹、确认快照和回执；同稳定教师 ID/幂等键唯一。请求指纹由草稿 ID、期望版本和排序后的记录 ID 组成；该版本的内容由不可变确认快照固定。先查原键再检查当前版本，响应丢失后的重放不会再次分析。一个草稿最多一个 `publishing`，数据库部分唯一索引保护占用。
- `homework_published_record` 主键为 `(draft_id,record_id)`，保留 `publication_id/item_id/evidence_id`，阻止换键重复发布。不会按学生最新证据猜测来源。
- `HomeworkImporter.prepare_rows(...)` 只读并调用现有模型分析；`write_prepared(session, prepared, teaching_date)` 在调用方事务内写正式结果，不自行提交。旧 `import_rows` 包装这两步，保持旧 CSV/CLI 语义。网页发布不重新发送 HTTP 或生成中间 CSV。
- 模型期间不持写锁；最终事务取得现有 SQLite 写锁，重新校验班级授权、草稿版本、成员及原题快照。题目、证据、账本状态、一个 `HomeworkImported`、`PendingWork`、回执、来源映射及记录已发布状态一次提交。
- 提交后调用 `recover_pending()`；只有现有 `_save_plan` 创建 Task。朱的编排通过只读 `event_workflow(event_id)` 提供现有规划节点回执与本进程失败集合的投影，返回 `pending/planned/failed` 及真实任务 ID；重启后未完成工作回到待恢复，不虚构持久化错误或教学完成结果。

### 状态、失败与恢复

- 草稿仍采用 `parsing/review/parse_failed/published`；另有 `active_publication_id` 表示发布占用。发布期间禁止修改、补图、再次解析；有待审记录时仍为 review，全部记录已发布或明确跳过时为 published。
- 缺字段、未核对或未处理疑点返回 422 `review_incomplete`，附逐记录 `issues`；版本/名单/题目/数据库冲突返回 409（最终导入阶段统一为 `import_conflict`）；无权资源 404，学生不能调用这些教师入口。
- 模型故障 502，未配置模型 503；确定未提交时整批回滚、回执 failed、释放占用，保留原稿。同键重放返回同一失败及原 HTTP 状态；修正后或重新尝试使用新键。错误体含 `detail:{code,message,retryable,publication_id}` 和已保存的 `publication`。
- 数据库异常时先查回执；若已成功则返回成功结果；暂无法确认时返回 503 和发布 ID，提示查询。服务启动扫描旧 publishing；单实例旧执行者已退出、且无原子成功提交时标为失败，允许新键重试，不增加发布队列或超时抢占机制。
- 已发布回执不会因规划失败回退或再次导入。页面展示规划待处理/失败；后续由原编排恢复，首期不新增公开的 Agent 重试接口。

### 分工与交付边界

柴负责审核 UI、发布入口、回执及导入事务适配；复用吴已交付的稳定教师 ID、班级和名单规则，不另建身份关系。朱继续负责作业事件之后的规划、任务与恢复；本实现只新增只读状态投影，不改教学决策或建立第二条任务创建链路。

自动建表并补齐历史草稿 JSON 默认字段，无需迁移学生或改写旧证据。验收采用优化计划的最小口径：三项定向检查（修改留痕、发布幂等、基本权限/不完整输入），复用既有草稿/导入/班级/编排检查，并进行一次教师浏览器主流程；不新增手写准确率、多格式全覆盖或压力评测。
